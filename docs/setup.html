Portfolio Automation

How the Salman Kalam portfolio stays in sync with GitHub repos, fresh screenshots, and secure credential handling.

Repo sync Screenshots MCP GitHub GitHub Actions

1. Credential model (security)

The only secret is a GitHub PAT. It must never appear in a committed file.

  • Local: stored in .env (gitignored).
  • CI: stored as the Actions secret GITHUB_PAT.
  • The GitHub MCP server reads it from the environment via interpolation ${GITHUB_PERSONAL_ACCESS_TOKEN} — the literal value is never written into opencode.json.

Required PAT scopes

ScopeWhy
repoRead repos, languages, topics; push commits (sync).
repo>workflowUpdate GitHub Actions workflow files if changed from API.
read:org (fine-grained)If repos live under an organization.

Tip: create a fine-grained PAT scoped to only this repo, not a broad classic token with all-scope access.

2. Local setup (one time)

  1. Copy .env.example → .env and paste your PAT.
  2. Start Docker (the GitHub MCP runs in a container).
  3. Verify: opencode should surface GitHub tools; scripts/sync_repos.py falls back to the env var if opencode.json has none.
# .env (local only, gitignored)
GITHUB_PERSONAL_ACCESS_TOKEN=ghp_XXXX

3. Repository sync

scripts/sync_repos.py calls the GitHub API to build repos.json:

  • Lists repos (with pages_enabled, pages_url, topics, languages).
  • Uses GraphQL to fetch the pinned repos (marked pinned: true).
  • Optionally applies AI enrichment (description, tags).

Run locally:

python scripts/sync_repos.py

4. Screenshots

scripts/capture-screenshots.js (Playwright) opens each Pages site and saves three images per repo into public/projects/<repo>/:

  • hero.png — top of page, desktop viewport.
  • full.png — full-page (after triggering lazy-load).
  • mobile.png — full-page at mobile width.

A 404 is detected via page title and recorded as screenshot_error: "404".

Local: uses system Chrome (channel: "chrome").
CI: auto-detects GITHUB_ACTIONS and uses Playwright's Chromium.

node scripts/capture-screenshots.js

5. GitHub Actions workflows

FileTriggerWrites
sync-repos.ymlDaily 06:00 + manualcommits repos.json
capture-screenshots.ymlDaily 06:15 + manualcommits PNGs + repos.json

Both run entirely on GitHub's hosted runners — no secrets in YAML aside from the Actions secret reference ${{ secrets.GITHUB_PAT }}.

6. FAQ

Do the MCP server and Playwright run on Actions?

MCP server — no. The GitHub MCP container provides tools to the agent interacting with you; Actions never runs it. Actions talks to GitHub directly via the PAT (web/REST call) in sync_repos.py.

Playwright — yes. The capture workflow installs Chromium headless and runs; no screen needed. Local runs use system Chrome, but that is only for your convenience.
