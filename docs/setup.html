1. Credential model (security)

The only secret is a GitHub PAT. It must never appear in a committed file.

  • Local: stored in .env (gitignored).
  • CI: stored as the Actions secret GITHUB_PAT.
  • The GitHub MCP server reads it from the environment via interpolation ${GITHUB_PERSONAL_ACCESS_TOKEN} — the literal value is never written into opencode.json.

Required PAT permissions

Use a fine-grained PAT (recommended) scoped to only your repos — do not grant a broad classic token. Below are the exact checkboxes to tick.

Creation steps (github.com → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token)

  1. Resource owner: your account (Salman Kalam).
  2. Repository access: "Only select repositories" — pick all repos you want tracked/hosted, or "All repositories".
  3. Permissions — under each category, set exactly:
CategoryPermissionAccessWhy
ActionsWorkflowsRead & writeCommit deploy-pages.yml into React repos.
AdministrationAdministrationRead & writeEnable GitHub Pages via the API.
ContentsContentsRead & writeRead code, list files, push repos.json/workflows, placeholders.
Metadata(always on)ReadRequired for every token; cannot be deselected.
PagesPagesWriteRead/host the Pages site and its URL.

A fine-grained token that can write workflow files already implies Administration write. Missing Actions → Workflows will make the script fail to write deploy-pages.yml for React repos.

Classic PAT alternative (if you prefer not to use fine-grained):

  • repo — full repo + Pages content.
  • workflow — allows updating workflow files.

3. Local setup (one time)

  1. Create the PAT with the exact permissions above.
  2. Store it locally: copy .env.example → .env and paste the token (no quotes). .env is gitignored, so it never gets committed.
  3. Add the token to GitHub Actions: repo → Settings → Secrets and variables → Actions → New repository secret → name GITHUB_PAT, value = the same token.
  4. Start Docker (the GitHub MCP runs in a container).
# .env (local only, gitignored)
GITHUB_PERSONAL_ACCESS_TOKEN=ghp_XXXX

Run everything locally

The scripts read the token from .env / env var first, then fall back to opencode.json — so local runs need no extra setup once .env exists.

4. Repository sync

scripts/sync_repos.py calls the GitHub API to build repos.json:

  • Lists repos (with pages_enabled, pages_url, topics, languages).
  • Uses GraphQL to fetch the pinned repos (marked pinned: true).
  • Optionally applies AI enrichment (description, tags).

Frontend hosting (auto)

For frontend repos, the script detects the publish source and enables Pages:

Repo contentBuild typeAction
Root index.htmllegacyenable_pages with path /
docs/index.htmllegacyenable_pages with path /docs
dist/index.htmlworkflowwrites .github/workflows/deploy-pages.yml (upload dist) + build_type: workflow
dist/client/index.htmlworkflowwrites deploy workflow (upload dist/client) + build_type: workflow

GitHub Pages' legacy API only accepts source paths / or /docs. React/Vite projects that build to dist/ therefore need the workflow build type and a committed deploy-pages.yml. The token must have the workflow scope for the script to write that file.

Only new repos are processed each run; existing tracked repos are left as-is.

Run locally:

python scripts/sync_repos.py

5. Screenshots

scripts/capture-screenshots.js (Playwright) opens each Pages site and saves three images per repo into public/projects/<repo>/:

  • hero.png — top of page, desktop viewport.
  • full.png — full-page (after triggering lazy-load).
  • mobile.png — full-page at mobile width.

A 404 is detected via page title and recorded as screenshot_error: "404".

Non-hosted repos (backend / data-analysis) get a generated placeholder: a repo tagged data analysis is copied to data_analysis.jpg, otherwise backend.jpg → projects/<repo>/hero.png.

Local: uses system Chrome (channel: "chrome").
CI: auto-detects GITHUB_ACTIONS and uses Playwright's Chromium.

node scripts/capture-screenshots.js

6. GitHub Actions workflows

Both run entirely on GitHub's hosted runners — no secrets in YAML aside from the Actions secret reference ${{ secrets.GITHUB_PAT }}. That secret holds the same PAT you put in .env locally, so one token covers both.

Note: the Actions GITHUB_PAT secret needs the same permissions (Administration, Actions → Workflows, Contents, Pages write) because the daily sync also auto-enables Pages and writes deploy workflows.

7. FAQ

Do the MCP server and Playwright run on Actions?

MCP server — no. The GitHub MCP container provides tools to the agent interacting with you; Actions never runs it. Actions talks to GitHub directly via the PAT (web/REST call) in sync_repos.py.

Playwright — yes. The capture workflow installs Chromium headless and runs; no screen needed. Local runs use system Chrome, but that is only for your convenience.
